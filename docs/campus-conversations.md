# Orbit 1.14.0 — Campus conversations

## The seven improvements
1. Compact Sea Glass feed cards: smaller author details, readable titles, expandable long text, reply previews and quieter actions. Existing Create and Search destinations remain separate from Home.
2. Six post purposes: Question, Discussion, Campus news, Looking for a group, Opportunity and Just for fun. Old demo flair values remain valid in saved data and map to the new presentation.
3. Discussions: two reply previews, a dedicated conversation view, Best/Latest ordering, collapsible branches, post-author labels and accepted answers. Cloud replies now support upvotes; Best promotes the accepted answer, then upvotes. Demo Best uses accepted answers, then the number of direct replies, and labels that rule. Cloud accepted answers are fetched separately when outside the current page. Deleting an accepted reply removes its accepted status.
4. Place: Across Orbit / My university / My campus shortcuts and optional school/topic/purpose filters. Guests can choose a campus; signed-in students use their own profile for shortcuts. Cloud school fields provide catalogue suggestions; profile campus details remain self-declared and must match the stored values. Following remains centred on people. Popular excludes private-circle posts even for members.
5. Around campus: contextual conversations, circles and people to follow. The existing demo Trending section remains. Desktop has a right column; phones have a collapsible section. Content comes from actual accessible data, with honest empty states. This release does not invent event listings or add an event-calendar service.
6. Circles: original vector cover presets (Sea Glass waves, garden and sky), an editable pinned introduction, rules, moderator identities and pinned conversations. Owners edit identity and moderators; moderators can pin approved accessible posts from that circle. Private-circle posts and private membership lists retain their existing access restrictions. Covers are presets, not media uploads.
7. Reading: return to the previous feed scroll position, new-reply count markers after reading, hide posts, mute topics and show fewer posts about a topic. Restore/reset controls are under My Profile, with an accessible reading-preferences dialog for guests. Cloud saved posts are now account-backed and shown under My Profile.

## Persistence and limits
Hide/mute/reduced-topic settings and read markers are device-local, separately keyed for each account and for demo/cloud mode. Storage failure keeps the current visit usable and is disclosed in reading settings. At most 500 entries per list/marker set are retained. Read indicators compare reply totals since the last read; deletions can affect the displayed difference. Hiding and muting filter browsing lists, not access to a directly opened post or the owner's saved list. Show fewer reorders the current For you page without silently dropping posts. It does not override Latest/Hot/Top ranking. Scroll restoration applies within the current browsing session.

The cloud feed loads 25 posts per page and at most two preview replies per post; discussions load 50 replies per request, with older-page controls. Missing parents across pages show an earlier-comment notice. Best sorting applies to loaded replies, with the accepted answer included independently. Context suggestions inspect a bounded candidate set; this is not a global recommendation engine. Public reading does not require an account. Posting, upvoting, saving, following, commenting and sharing require an account.

The full demo and cloud pilot remain separate. Demo social data is not uploaded. Existing cloud messages, games and account flows are retained. Polls, reposts/quotes, awards, advanced hashtag discovery and full profile activity parity are still demo features. There is no Realtime subscription or push notification service in this release.

## Database and deployment
Migration: supabase/migrations/20261027174712_campus_discussions.sql. Adds post purpose/accepted-answer fields, reply vote counts, circle identity/pin fields and two RLS-protected tables for saves and comment votes. Direct client writes remain revoked; checked gateway routes enforce actor identity, ownership, visibility and moderator roles. New foreign keys have supporting indexes. Applied through the dashboard SQL Editor with the API iterated there; canonical source contains the final definition. Reconcile remote migration history before using db push, as explained in the cloud pilot document.

No credentials or service keys were placed in the frontend. The SMTP/confirmed-account pilot limitation remains. The security advisor currently reports the existing Leaked Password Protection Disabled Auth warning; that protection requires Pro or above according to https://supabase.com/docs/guides/auth/password-security. No plan upgrade or authentication weakening was performed.
